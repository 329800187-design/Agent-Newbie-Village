## 一、v1.0 开发总览

### 1.1 开发目标

基于 v4.0 产品方向设计和 v1.0 执行版设计修正文档，开发一份完整的、可玩的、能验证产品假设的最小可用产品（MVP）。

**产品假设：**
1. 零基础小白愿意玩闯关游戏形式的学习产品
2. 选词拼装交互比手动输入更适合小白
3. AI认知层贯穿全程能让用户理解"为什么要学这些"
4. 地图闯关结构能让用户第一眼感觉"这是一个游戏"

### 1.2 开发范围

| 模块 | 内容 | 关卡数 |
|------|------|--------|
| AI启蒙营 | AI认知基础 | 5关 |
| W1 黑窗口村 | PowerShell终端 | 8关 |
| W2 代码森林 | 编程逻辑 | 6关 |
| 地图系统 | 纵向闯关地图 | 19个节点 |
| 小黑NPC | 向导对话系统 | 全程 |
| 认证系统 | 3个认证 | AI认知入门、终端操作员、逻辑入门 |
| 词典系统 | 命令词典 + 概念词典 | 全程 |
| 成就系统 | XP + 星级 | 全程 |

### 1.3 技术边界

**继续单 HTML 文件，内部分区。**

不做：
- React / Electron / 后端
- 用户账号 / 云同步
- 真实Python执行 / 真实C执行 / 真实系统命令执行
- 社区 / 排行榜 / 商城

只做：
- 模拟执行
- CSS渐变 + SVG路径 + 圆形节点（地图视觉）
- 基础动画（呼吸、星星落下、节点点亮）
- localStorage存档

## 二、开发阶段划分

### 2.1 阶段总览

| 阶段 | 名称 | 任务数 | 核心交付 | 依赖 |
|------|------|--------|----------|------|
| 阶段1 | 地图外壳 + State + LevelData + 调试入口 | 10 | 可交互地图 + 进度系统 + 调试面板 | 无 |
| 阶段2 | 关卡信息卡 + 节点状态 | 5 | 点击节点弹出信息卡 + 状态更新 | 阶段1 |
| 阶段3 | W1终端关卡接入 | 8 | W1全8关可玩 | 阶段2 |
| 阶段4 | AI启蒙营接入 | 6 | AI启蒙营5关可玩 | 阶段2 |
| 阶段5 | W2逻辑积木接入 | 8 | W2全6关可玩 | 阶段2 |
| 阶段6 | 认证、词典、成就、反馈动画 | 7 | 完整反馈系统 | 阶段3/4/5 |
| 阶段7 | 全流程测试 | 6 | 可发布版本 | 阶段6 |

### 2.2 为什么先做地图外壳

**核心原则：用户第一眼必须感觉"这是一个游戏"，而不是"一个黑色终端教程"。**

如果先改W1关卡内容，用户打开游戏看到的还是黑色终端界面，会立刻产生"这是一个编程教程"的认知，增加学习恐惧。

正确顺序：
1. 先做地图闯关页面（让用户第一眼看到游戏）
2. 再做State进度系统（让地图有状态）
3. 再做LevelData统一关卡结构（让关卡数据可管理）
4. 再接入关卡信息卡（让用户知道每关学什么）
5. 再改W1终端内容（让用户实际玩关卡）
6. 再加AI启蒙营（让用户从认知开始）
7. 再做W2代码森林（让用户理解编程逻辑）
8. 最后做认证和完成反馈（让用户有成就感）

  if (state.completed) return "completed";

function completeLevel(levelId, stars) {
  // 更新State
  State.levels[levelId].completed = true;
  State.levels[levelId].stars = stars;
  
  // 解锁下一关
  const nextLevel = getNextLevel(levelId);
  if (nextLevel) {
    State.levels[nextLevel].unlocked = true;
  }
  
  // 更新地图节点
  updateNodeState(levelId, "completed");
  if (nextLevel) {
    updateNodeState(nextLevel, "current");
  }
  
  // 小黑移动到下一关
  State.kuonPosition = nextLevel;
  updateKuroPosition();
  
  // 保存进度
  State.save();
}
```

function parseCommand(input) {
  // 输入格式：["Get-Location"] 或 ["Set-Location", "文档"]
  
  const cmd = input[0];
  const args = input.slice(1);
  
  // 支持中文别名
  const realCmd = resolveAlias(cmd);
  
  // 执行命令
  switch (realCmd) {
    case "Get-Location":
      return VFS.pwd();
    case "Set-Location":
      return VFS.cd(args[0]);
    // ... 其他命令
  }
}

function resolveAlias(cmd) {
  // 如果输入的是中文别名，转换为真实命令
  const aliasMap = {
    "我在哪": "Get-Location",
    "看看": "Get-ChildItem",
    "去": "Set-Location",
    // ...
  };
  
  return aliasMap[cmd] || cmd;
}
```

function validateLogic(logicBlocks, correctLogic) {
  // 验证逻辑积木顺序是否正确
  if (logicBlocks.length !== correctLogic.length) return false;
  
  for (let i = 0; i < logicBlocks.length; i++) {

  }
  
  return true;
}

### 11.2 CSS动画性能优化

**使用transform和opacity，避免触发重排：**

```css
/* ✅ 好：使用transform */
@keyframes breathe {
  0% { transform: scale(1); }
  50% { transform: scale(1.1); }
  100% { transform: scale(1); }
}

/* ❌ 差：使用width/height */
@keyframes breathe-bad {
  0% { width: 50px; }
  50% { width: 55px; }
  100% { width: 50px; }
}
```

### 11.3 localStorage使用规范

**存档频率：**
- 每关完成后立即存档
- 不要每次状态变化都存档（性能）

**存档大小：**
- 只存必要数据（进度、XP、星级、认证）
- 不存关卡数据（LevelData是静态的）
- 估算：19关 × 每关100字 = 约2KB，很小

**存档格式：**
```javascript
const saveData = {
  version: "1.0",
  timestamp: Date.now(),
  state: State // 只存必要字段
};

localStorage.setItem("agent_village_save", JSON.stringify(saveData));
```
