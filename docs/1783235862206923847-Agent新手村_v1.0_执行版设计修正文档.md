## 二、核心 UI 方向修正：主界面必须是"地图闯关游戏"

### 2.1 为什么要改

当前设计的世界地图是"卡片列表"形式——几个矩形卡片并排排列，显示世界名称和状态。

问题是：用户第一眼看到卡片列表，会觉得"这是一个课程列表"或"一个教程目录"，而不是"一个游戏"。

参考闯关游戏地图的结构，Agent 新手村的主界面必须让用户第一眼感觉到：

"这是一个闯关游戏，我可以点关卡往前走。"

而不是：

"这是一个黑色终端教程，我看不懂。"

### 2.2 地图闯关结构的核心要素

从参考图中吸收的结构（不是美术素材，而是结构）：

| 结构要素 | 作用 | Agent 新手村中的对应 |
|----------|------|---------------------|
| 弯曲道路 | 学习路径 | SVG 曲线路径串联 19 个关卡节点 |
| 圆形关卡点 | 每一关 | 关卡节点（可点击） |
| 数字节点 | 关卡编号 | 节点上显示关卡编号 |
| 星星 | 通关评分 | 零提示通关得 3 星 |
| 锁定节点 | 后续内容未解锁 | 灰色 + 锁图标 |
| 角色站位 | 当前位置 | 小黑站在当前关卡节点旁 |
| 底部按钮 | 功能入口 | 地图、小黑、词典、成就、设置 |
| 大地图区域 | 不同世界主题 | 3 个已开放区域 + 后续锁定区域 |
| Boss 节点 | 每个世界最终关 | 节点更大、边框更明显、特殊图标 |

### 2.3 关键原则

- **黑色终端只出现在 W1 的关卡内部**，不能成为整个产品的主视觉
- **地图本身不要全黑**，每个区域有自己的主题色和视觉元素
- 终端是关卡内部的操作工具，地图是游戏的外壳
- 用户打开游戏第一眼看到的是地图，不是终端

## 四、地图节点设计

### 4.1 节点状态

每个关卡节点都有以下状态之一：

**1. 未解锁**

- 灰色显示
- 锁图标
- 不可点击，或点击后显示解锁条件（"完成前一关后解锁"）

**2. 当前关**

- 高亮发光
- 小黑站在节点旁边
- 节点轻微呼吸动画（缩放 + 发光脉冲）
- 这是用户接下来要做的关卡

**3. 已完成**

- 亮色显示
- 显示星级（0-3 星）
- 可点击回顾
- 节点上有星星图标

**4. Boss 关**

- 节点更大
- 边框更明显
- 有特殊图标（如皇冠、骷髅、旗帜等）
- 完成后触发区域认证卡片

### 4.2 节点显示信息

每个节点必须显示：

| 信息项 | 说明 |
|--------|------|
| 关卡编号 | 节点上的数字 |
| 状态 | 未解锁 / 当前 / 已完成 / Boss |
| 星级 | 0-3 星（零提示通关 = 3 星） |
| 是否 Boss | Boss 关有特殊标记 |

### 4.3 节点点击行为

用户点击地图节点后，**不直接进入关卡**，而是先弹出"关卡信息卡"。

只有用户在关卡信息卡上点击"开始挑战"后，才进入关卡。

这样做的原因：
- 让用户在进入关卡前，明确知道"这关学什么、为什么要学"
- 给用户一个心理准备的时间
- 避免误触进入关卡

## 六、关卡完成反馈

### 6.1 完成后回到地图

完成关卡后必须**回到地图**，而不是只显示"下一关"按钮。

这样做的原因：让用户在地图上看到自己的进度推进，产生"我在闯关"的感觉。

### 6.2 完成反馈内容

```
┌──────────────────────────────────┐
│  ✅ 第3关完成！                   │
│                                   │
│  获得 +100 XP                     │
│  获得 ⭐⭐⭐ 零提示奖励             │
│                                   │
│  地图节点 3 已点亮                │
│  小黑移动到第4关                  │
│  第4关已解锁                      │
│                                   │
│  [回到地图]                       │
└──────────────────────────────────┘
```

### 6.3 地图上的变化

关卡完成后，地图上发生以下变化：

1. **当前节点点亮**：从"当前关"状态变为"已完成"状态，显示星级
2. **星星落到节点上**：有星星动画落在节点上
3. **XP 进度条增长**：顶部或底部的 XP 条增长
4. **小黑移动到下一关**：小黑从当前节点移动到下一关节点
5. **下一关节点解锁**：从"未解锁"变为"当前关"
6. **区域完成时弹出认证**：如果完成的是该区域最后一关，弹出区域认证卡片

## 八、关卡内容修正（8 项）

以下是进入开发前必须修改的教学设计问题。

---

### 修正1：AI 启蒙营第4关"幻觉"例子改为游戏内事实判断

**问题：** 原设计用"中国第一部宪法是哪一年"作为幻觉示例，用户可能不是因为理解"幻觉"才答对，而是因为知道或不知道历史知识。这会混淆"AI幻觉"和"历史知识"两个维度。

**修正方案：**

改为游戏内事实判断——用游戏世界里不存在的东西来测试。

**新设计：**

小黑问 AI：

> "黑窗口村里有没有一个叫红帽法师的 NPC？"

AI 回答：

> "有，红帽法师住在村口左边的小屋里，他会教你基础命令。"

但游戏地图里根本没有这个 NPC。用户从一开始就在地图上看到了黑窗口村的所有角色，里面没有红帽法师。

**用户任务：**

判断这是不是 AI 幻觉。

**选项：**

- A. 这是 AI 幻觉，黑窗口村里没有红帽法师（正确）
- B. AI 说得对，可能有红帽法师
- C. AI 不会出错，应该是真的
- D. 不确定

**正确认知：**

AI 有时会自信地编出不存在的信息。所以 AI 输出必须验收。

**AI 视角解释：**

```
你刚学会：AI 会编出不存在的信息。
Agent 用在哪：Agent 也可能输出虚构内容。
以后怎么用：让 Agent 做事后必须核实结果。
不会会怎样：你可能把假信息当真，交付出去。
```

---

### 修正2："AI 只是预测下一个词"表述补充完善

**问题：** 原设计说"AI 只是预测下一个最可能的词"，这个说法太绝对，可能让用户觉得 AI 很低级或完全没用。

**修正方案：**

保留"预测下一个词"的解释，但补充上下文，避免用户产生错误认知。

**新表述：**

> AI 不是像人一样真正理解世界。
> 它主要是根据你给的上下文，生成最可能、最像答案的内容。
> 所以它很有用，但也可能自信地说错。

**在 AI 启蒙营第1关中的应用：**

小黑的对话改为：

> "AI 不是人。它不会像人一样'理解'你说的话。
> 它主要是根据你给的上下文，生成最可能、最像答案的内容。
> 但这不代表它没用！AI 可以帮你写文章、写代码、分析问题。
> 只是它需要你的引导和监督——因为它可能自信地说错。"

**选词拼装任务调整：**

词块改为：
- [AI 不是人]（正确）
- [AI 根据上下文生成最可能的内容]（正确）
- [AI 真正理解世界]（错误）
- [AI 有感情和意识]（错误）

正确答案：选前两个。

### 修正3：AI 启蒙营第2关 Prompt 改为选词拼装任务

### 修正6：W2 代码森林改为"逻辑积木 + 类 Python 伪代码预览"

**问题：** 原 W2 设计虽然说是"教编程逻辑"，但实际交互方式仍然是让用户选 Python 代码词块（如 `def greet(name):`），本质上还是在教 Python 语法。对小白来说，直接面对代码语法会造成挫折。

**修正方案：**

W2 的主要交互改为"逻辑积木"——用户操作的是中文逻辑卡片，不是代码。

代码只放在旁边作为预览，标注为"类 Python 伪代码"，让用户先理解逻辑，再逐步熟悉代码长什么样。

**交互结构：**

```
┌──────────────────────┬──────────────────────┐
│                      │                      │
│   左侧：逻辑积木操作   │  右侧：伪代码预览      │
│                      │                      │
│  [保存名字为 name]   │  name = "小明"       │
│  [输出 你好 + name]  │  print("你好，" + name)│
│                      │                      │
│  ┌─────────────┐    │                      │
│  │ 可用积木     │    │                      │
│  │ [保存___为___]│    │                      │
│  │ [输出___]    │    │                      │
│  │ [如果___就___]│    │                      │
│  │ [重复___次___]│    │                      │
│  └─────────────┘    │                      │
│                      │                      │
└──────────────────────┴──────────────────────┘
```

**设计要点：**

1. **左侧是逻辑积木**：用户拖拽或点击中文逻辑卡片来组装逻辑
2. **右侧是伪代码预览**：用户操作积木时，右侧实时显示对应的"类 Python 伪代码"
3. **代码标注为"类 Python 伪代码"**：不强调语法准确性，强调逻辑对应
4. **用户不需要写代码**：只需要理解逻辑积木的含义和顺序

**示例：W2 第1关 变量**

逻辑积木：

```
[保存 "小明" 为 name]
[输出 "你好，" + name]
```

类 Python 伪代码预览：

```python
name = "小明"
print("你好，" + name)
```

用户任务：从可用积木中选择正确的两块，按顺序拼装。

**示例：W2 第2关 条件**

逻辑积木：

```

[如果 question 包含 "代码"]
[就输出 "我来帮你写代码"]
[否则]
[就输出 "我不确定怎么帮你"]
```

```python
question = input()
```

逻辑积木：

```

[输出 "Hello!"]
```

类 Python 伪代码预览：

```python
for i in range(5):
    print("Hello!")
```

**示例：W2 第4关 函数**

逻辑积木：


## 十三、AI 视角解释组件设计（修正版）

### 13.1 组件结构

固定 4 行，每行不超过 25 字，总字数 80-120 字。

```
┌──────────────────────────────────┐
│  🤖 AI 视角解释                   │
│                                   │
│  你刚学会：查看当前位置。          │
│  Agent 用在哪：执行前确认位置。    │
│  以后怎么用：操作文件前先看路径。  │
│  不会会怎样：Agent 可能找错文件。  │
│                                   │
│  [下一关 →]                      │
└──────────────────────────────────┘
```

### 13.2 内容要求

| 部分 | 要求 | 字数限制 |
|------|------|----------|
| 你刚学会 | 一句话总结本关内容 | ≤25字 |
| Agent 用在哪 | 一句话映射到 Agent 环节 | ≤25字 |
| 以后怎么用 | 一句话给出使用场景 | ≤25字 |
| 不会会怎样 | 一句话说明后果 | ≤25字 |
| **总计** | **4行** | **80-120字** |

### 13.3 在游戏中的实现

1. 有固定的视觉样式（特殊边框 + 🤖 图标 + 浅色背景）
2. 不能跳过：用户必须看完才能点"下一关"
3. 可以回顾：在"关卡回顾"里可重新查看
4. 小黑偶尔补充一句话，增加人格感

## 十四、小黑 NPC 在 v1.0 的表现（修正版）

### 14.1 小黑的定位（不变）

- v1.0 中小黑暂时不暴露自己是 Agent
- 只表现为新手向导
- v1.0 身份：用户的向导和朋友

### 14.2 小黑的说话方式

| 要求 | 说明 |
|------|------|
| 不要太学术 | 用大白话，不用术语 |
| 不要太长 | 每次说话控制在 2-3 句 |
| 要像队友 | 不是"老师对学生"，而是"老手带新手" |
| 可以幽默 | 偶尔吐槽、开玩笑 |
| 但不能废话太多 | 有信息量，不纯凑数 |
| 出错时给提示 | 不嘲讽，渐进式提示 |
| 完成时制造成就感 | 鼓励但不肉麻 |

### 14.3 小黑在地图上的表现

小黑在地图上站在当前关卡节点旁边，有以下表现：

| 状态 | 表现 |
|------|------|
| 等待用户操作 | 站在当前节点旁，偶尔眨眼或动一下 |
| 用户进入关卡 | 小黑出现在关卡内部，作为向导 |
| 用户出错 | 小黑给出三段式提示（暗示→明示→答案） |
| 用户做对 | 小黑说鼓励的话（短句） |
| 关卡完成 | 小黑移动到下一关节点 |
| 区域完成 | 小黑说庆祝的话 + 预告下一区域 |

### 14.4 小黑三段式提示

```
第1次错（暗示）：
  小黑："想想看，你想'我在哪'，应该用哪个命令？"

第2次错（明示方向）：
  小黑："Get-Location = 获取位置 = 我在哪。你想知道位置，应该用它。"

第3次错（给答案）：
  小黑："正确答案是 Get-Location。来，我们看看它什么意思..."
```

## 十七、开发优先级确认

### 17.1 开发顺序

**不要先直接改 W1 关卡内容。**

正确顺序是：

```
第一阶段：地图外壳和状态骨架
  1. 大地图容器
  2. 区域背景：AI启蒙营、黑窗口村、代码森林
  3. SVG 弯曲路径
  4. 19 个关卡节点
  5. 节点状态系统
  6. 小黑当前位置
  7. 点击节点弹出关卡卡片
  8. State 进度系统
  9. LevelData 统一结构

第二阶段：接入 W1
  1. PowerShell 命令体系
  2. 中文别名
  3. 单词拆解卡片
  4. 选词拼装
  5. 三段式提示
  6. W1 8 关（含修正后的 Boss 战）
  7. 终端模拟器面板

第三阶段：接入 AI 启蒙营
  1. AI 启蒙营 5 关
  2. Prompt 拼装任务
  3. 游戏内幻觉判断（红帽法师）
  4. AI 视角解释组件

第四阶段：接入 W2
  1. 逻辑积木面板
  2. 伪代码预览面板
  3. W2 6 关（含修正后的 Boss 战）
  4. 流程卡片排序

第五阶段：认证与反馈
  1. 关卡完成动画
  2. 地图节点点亮
  3. 星级奖励
  4. XP 增长
  5. 小黑移动到下一关
  6. 区域认证卡片
```

### 17.2 为什么先做地图

**如果没有地图闯关外壳，关卡内容再好，小白第一眼也会觉得是在看黑色终端教程。**

v1.0 第一目标是：

1. 让用户第一眼觉得这是游戏
2. 让用户点节点进入挑战
3. 让用户通关后看到地图推进
4. 让用户愿意继续下一关

所以地图外壳必须先做，再接入关卡内容。
