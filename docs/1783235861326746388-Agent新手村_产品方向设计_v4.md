## 一、产品一句话定义

**用游戏化方式，让零基础小白从"不懂 AI、不懂终端、不懂代码"，成长为"能理解 AI、能指挥 Agent、能搭建简单自动化工作流"的 AI Agent 操作员。**

---

## 二、产品最终定位

《Agent新手村》不是一个普通编程课，也不是一个轻量 Agent 小游戏。

它的最终定位是：

**面向零基础小白的 AI Agent 操作员闯关训练系统。**

产品目标不是把用户培养成传统程序员，而是让用户通过游戏化闯关，逐步建立和 AI 协作的能力，最终能够理解 AI、操作 Agent、配置基础环境、看懂基础代码、搭建简单智能体和工作流。

### 不是什么

- 不是普通编程课（不以培养程序员为目标）
- 不是 AI 理论课（不教 Transformer、神经网络、反向传播）
- 不是纯娱乐游戏（有真实的教学目标和能力交付）
- 不是技术文档（不用学术语言，用小白能懂的话）

### 是什么

- 一个闯关训练系统（有明确的成长路径和能力交付）
- 一个认知建模工具（帮助用户建立"AI 如何工作"的心智模型）
- 一个游戏化学习产品（用游戏机制降低学习恐惧和抵触）
- 一个操作员训练系统（最终目标是"能操作"，不是"能研究"）

## 三、目标用户

### 核心用户画像

**完全零基础的小白。** 具体特征：

| 特征 | 说明 |
|------|------|
| 技术背景 | 不知道终端是什么，不知道 Unix 是什么，没写过代码 |
| 心理状态 | 看到英文命令和代码会本能恐惧，对学习新技术有抵触 |
| 电脑能力 | 有基础电脑操作能力（会用浏览器、装软件、用微信），但不会编程 |
| 学习动机 | 想学 AI / Agent，但不知道从哪开始，被各种教程劝退 |
| 认知特点 | 注意力投入有限，需要低认知负荷的设计 |

### 用户心理模型

这类用户面对技术学习时，内心活动是：

```
看到英文命令 → "这是什么？我看不懂" → 挫败感 → 想放弃
看到代码 → "这跟我有什么关系" → 无聊 → 想放弃
看到长篇解释 → "太长了不想看" → 跳过 → 什么没学到
能点到按钮就直接点 → "懒得打字" → 偷懒 → 什么没学到
不知道为什么要学这个 → "学这个干嘛" → 失去动力 → 想放弃
```

**产品设计必须针对这些心理反应逐一破解。**

## 四、用户最终能获得什么能力

用户走完全程后，能够：

1. **理解 AI 是什么、能做什么、不能做什么**
2. **理解 Prompt、上下文、幻觉、验收的重要性**
3. **掌握基础 PowerShell 终端操作**
4. **理解基础编程逻辑：变量、条件、循环、函数**
5. **能写基础 Python 脚本**
6. **能看懂和修改基础 C 语言代码**
7. **理解程序运行环境、依赖、PATH、API Key、虚拟环境**
8. **理解 Agent 的组成：模型、工具、环境、记忆、任务循环**
9. **能拆解任务、写清楚指令、验收 AI 结果、纠正错误**
10. **能搭建一个简单的个人 Agent 工作流**

### 能力之间的逻辑关系

```
理解 AI 边界
    ↓
会用终端（Agent 操作文件/系统的手）
    ↓
理解编程逻辑（Agent 判断、分支、循环的思维基础）
    ↓
会写 Python（Agent 工具和自动化脚本的主要载体）
    ↓
理解环境配置（Agent 的生存空间）
    ↓
理解 C 语言底层（理解程序为什么这样运行）
    ↓
理解 Agent 原理（模型、工具、环境、记忆、循环的组合）
    ↓
能搭建工作流（把多个 Agent 步骤固定成可复用流程）
```

## 五、AI 认知层设计：贯穿全程的认知底座

### 核心设计原则

**AI 认知层不是单独的一个世界，而是贯穿所有世界的"解释器层"。**

也就是说，AI 认知应该像游戏里的 HUD、地图、任务提示一样，持续存在于每个世界、每一关里。

每一关都必须回答三个问题：

1. **为什么要学这个？**
2. **现在具体怎么操作？**
3. **这个能力以后怎么用于 AI / Agent？**

### 5.1 动机解释

告诉小白为什么要学当前内容。

| 当前学的 | 动机解释（小白能懂的话） |
|----------|--------------------------|
| 终端 | Agent 操作电脑、读取文件、执行任务时，底层经常需要命令能力。学会终端，你就能理解 Agent 是怎么"动手"的。 |
| 编程逻辑 | Agent 做判断、重复执行、拆任务、调用工具，背后都是编程逻辑。学会逻辑，你就能理解 Agent 是怎么"思考"的。 |
| Python | 很多 Agent 工具本质上就是 Python 函数。学会 Python，你就能看懂、修改、甚至自己写 Agent 工具。 |
| 环境配置 | Agent 不是凭空运行的，它需要 Python、依赖、API Key、PATH、虚拟环境。学会环境配置，你就能给 Agent 搭建"厨房"。 |
| C 语言 | C 可以帮助你理解程序为什么需要编译、内存是什么、指针为什么代表地址。学会 C 语言底层，你就不会把电脑和程序当成黑盒。 |
| Agent 原理 | 前面学的所有东西——终端、逻辑、Python、环境、底层——都在这里汇合成 Agent 能力。学会原理，你就能指挥 Agent。 |
| 工作流 | 单个 Agent 任务还不够，你需要把多个步骤串联起来，固定成可复用的流程。学会工作流，你就能让 AI 真正帮你干活。 |

### 5.2 技术映射

每个世界都要绑定到 Agent 能力上。

| 世界 | Agent 能力映射 |
|------|----------------|
| AI 基础认知 | 正确认识 AI 的能力 |
| PowerShell 终端 | Agent 操作文件和系统的手 |
| 编程逻辑 | Agent 判断、分支、循环、拆任务的思考基础 |
| Python | Agent 工具和自动化脚本的主要载体 |
| 环境配置 | Agent 的生存空间 |
| C 语言 | 理解程序运行、编译、内存和底层错误的基础 |
| Agent 原理 | 模型、工具、记忆、环境、循环的组合 |
| 工作流 | 把多个 Agent 步骤固定成可复用生产流程 |

### 5.3 认知防崩

小白必须提前理解 AI 的边界，避免错误认知。

必须讲清楚：

- **AI 不是人**——它没有真实理解，只是预测下一个最可能的词
- **AI 不是搜索引擎升级版**——它会自信地说错话
- **AI 不一定永远正确**——需要人工验收
- **AI 输出的是初稿，不是最终答案**——人要做最后把关
- **AI 需要清楚的上下文**——Prompt 写得越清楚，结果越容易验收
- **Prompt 写得越清楚，结果越容易验收**——这是可学习的技能
- **Agent 是带工具的大脑，不是魔法**——它有明确的组成和结构
- **工作流是把多步任务固定下来，重复执行**——不是让 AI 自由发挥

## 六、新手引导：AI 启蒙营

### 定位

让小白先知道 AI 是什么、Prompt 是什么、AI 为什么会错、Agent 和普通 AI 有什么区别。

**不作为正式大世界，只做 4～5 个小关卡，作为进入主线前的引导。**

### 内容

| 关卡 | 标题 | 教学内容 |
|------|------|----------|
| 1 | AI 是什么，不是什么 | AI 的能力边界，不是人，不是魔法 |
| 2 | Prompt 是什么 | 如何跟 AI 说话，上下文的重要性 |
| 3 | AI 为什么会出错 | 幻觉是什么，为什么要验收 AI 输出 |
| 4 | Agent 和普通 AI 的区别 | Chatbot vs Agent，工具的概念 |
| 5 | AI、工具、Agent、工作流的关系 | 从单轮对话到自动化工作流的完整图景 |

### 注意事项

- **不要讲 Transformer、神经网络数学、模型训练、反向传播、参数量、向量数据库这些复杂内容**
- AI 启蒙营的作用不是教理论，而是让小白形成正确使用 AI 的基本认知
- 用大白话，不用学术术语
- 每关都要有"啊哈时刻"——让用户感受到"原来 AI 是这样的"

### 9.1 AI 启蒙营（引导模块）

**定位：** 让小白先建立正确 AI 使用观，不迷信 AI，不害怕 AI，也不误解 AI。

4. AI 为什么会出错，什么叫幻觉

**Agent 映射：** AI 基础认知 = 正确认识 AI 的能力

**注意事项：** 不讲理论，只建立认知；用大白话；每关有"啊哈时刻"

### 9.2 W1：黑窗口村（PowerShell 终端）— 8 关

**定位：** 让小白不再害怕黑窗口，理解基础命令操作。

**核心命令设计：**

采用 PowerShell 风格命令 + 中文别名 + 单词级拆解。

| 沙盒命令 | 中文含义 | 单词拆解 | 真实 PowerShell | 真实 Unix（了解即可） |
|---------|---------|---------|---------------|-------------------|
| Get-Location | 我在哪 | Get=获取 Location=位置 | Get-Location（别名: pwd） | pwd |
| Get-ChildItem | 看看有什么 | Get=获取 Child=子 Item=项目 | Get-ChildItem（别名: ls） | ls |
| Set-Location | 去某个地方 | Set=设置 Location=位置 | Set-Location（别名: cd） | cd |
| Get-Content | 打开看看 | Get=获取 Content=内容 | Get-Content（别名: cat） | cat |
| New-Item | 新建 | New=新建 Item=项目 | New-Item | mkdir/touch |
| Remove-Item | 删除 | Remove=移除 Item=项目 | Remove-Item（别名: rm） | rm |
| Copy-Item | 复制 | Copy=复制 Item=项目 | Copy-Item（别名: cp） | cp |
| Write-Output | 输出 | Write=写出 Output=输出 | Write-Output（别名: echo） | echo |
| Select-String | 搜索 | Select=选择 String=字符串 | Select-String（别名: sls） | grep |

**必须保留的设计：**
- PowerShell 命令
- 中文别名（输入"看看"等同于 `Get-ChildItem`）
- 单词级释义（每个新命令弹出单词拆解卡片）
- 真实命令对照（命令执行后显示"这相当于真实终端里的 `Get-ChildItem`（或 `ls`）"）
- 选词拼装（替代手动输入）
- 渐进式提示（删掉"帮我填入"按钮，改为提示按钮，3 次提示后才给答案）

**Agent 映射：** 终端能力 = Agent 操作文件、目录、系统的基础。

**关卡设计：**

| 关卡 | 标题 | 教学内容 | 关键设计 |
|------|------|----------|----------|
| 1 | 初识终端 | Get-Location（我在哪） | 命令词典卡片首次出现 |
| 2 | 看看周围 | Get-ChildItem（看看有什么） | 选词拼装输入 |
| 3 | 去别的地方 | Set-Location（去某个地方） | 文件树可视化 |
| 4 | 打开文件 | Get-Content（打开看看） | 啊哈时刻：发现隐藏文件 |
| 5 | 新建东西 | New-Item（新建） | 自由操作 |
| 6 | 删除和复制 | Remove-Item / Copy-Item | 练习关 |
| 7 | 搜索文本 | Select-String（搜索） | 彩蛋关：搜索彩蛋信息 |
| 8 | Boss 战 | 管道符 \| + 综合应用 | Boss 战 |

### 9.4 W3：Python 花园（Python 脚本）— 8 关

**定位：** Python 不是为了刷题，也不是为了培养传统程序员，而是为了让用户理解 Agent 工具和自动化脚本。

**教学深度：** 教到"能写"。用户通关后能独立写简单的 Python 脚本。

**核心内容：**
- print
- 变量
- 字符串
- if 判断
- 循环（for/while）
- list / dict
- 函数
- 文件读写

**Agent 映射：**
- Python 函数 = Agent 工具的基础形态
- Python 脚本 = Agent 自动化执行任务的重要方式

**关键设计：**
- 新增代码编辑器面板（语法高亮 + 运行按钮）
- MVP 阶段模拟执行（模式匹配预设结果）
- 选词拼装 → 逐步过渡到自由编写（前 4 关选词，后 4 关自由写）
- 每关结尾有小练习，用户独立写一段代码
- 每关结束必须有"AI 视角解释"

### 9.5 W4：环境工坊（环境配置）— 6 关

**定位：** 让小白理解程序和 Agent 不是凭空运行的，它们需要环境。

**核心内容：**

### 9.6 W5：C 语言矿山（底层理解）— 8 关

**定位：** C 语言不是为了就业转码，而是为了让小白理解程序运行的底层逻辑。

**教学深度：** 教到"能看懂+能改"。重点是"能看懂、能改、知道程序为什么这样运行"。

**核心内容：**
- main 函数
- printf / scanf
- 变量类型
- 编译流程
- if / for / while
- 函数
- 数组
- 指针浅讲
- 内存地址可视化

**注意事项：**
- C 语言不要做成完整就业课，不讲过深内容
- 重点是"能看懂、能改、知道程序为什么这样运行"
- 指针用"内存地图"可视化——把内存画成一排格子，指针是指向某个格子的箭头

**Agent 映射：** C 语言 = 帮助用户理解底层运行、编译错误、内存、地址和程序执行过程。它让用户不再把电脑和程序当成黑盒。

**关卡设计：**

| 关卡 | 标题 | 教学内容 | 关键设计 |
|------|------|----------|----------|
| 1 | 你好，C | #include、main()、printf、编译流程 | 编译模拟可视化 |
| 2 | int 与 float | int/float/char/double、变量声明 | 类型匹配游戏 |
| 3 | 输入与输出 | scanf、printf 格式化符 | 输入输出模拟 |
| 4 | 判断与选择 | if/else、switch-case | 流程图拼装 |
| 5 | 循环挖掘 | for/while/do-while | 循环可视化 |
| 6 | 函数矿洞 | 函数声明、参数、返回值 | 函数组装 |
| 7 | 数组矿车 | 数组声明、遍历、字符数组 | 数组可视化 |
| 8 | 指针初探 | & 取地址、* 解引用、指针与数组 | 内存可视化 + 综合项目 |

### 9.7 W6：智能体工坊（Agent 原理）— 8 关

**定位：** 让用户理解 Agent 不是魔法，而是模型、工具、环境、记忆、任务循环组合起来的系统。

**核心内容：**
1. Chatbot vs Agent
2. 工具是什么
3. API 调用是什么
4. Agent Loop
5. 观察 → 思考 → 行动 → 观察
6. 工具选择
7. 任务拆解
8. Prompt 基础
9. **小黑原来也是 Agent 的认知闭环**

**Agent 映射：** 这里是前面所有知识的汇合点。用户会发现，前面学的终端、Python、环境、逻辑，都在这里变成 Agent 能力。

**关键设计：**

| 关卡 | 标题 | 教学内容 | 关键设计 |

**关卡 5 的设计（认知闭环）：**

```

    你就可以理解我是怎么工作的了。
```

这一刻是整个产品的情感高潮和认知高潮。

## 十、每关统一教学结构

每一关必须统一成固定教学结构。

### 10.1 放弃过重的 7 步教学闭环

之前的 7 步教学闭环（开场→互动→解释→伪代码→预测→答案→总结）对简单关卡来说过重，对复杂关卡来说不够。

### 10.2 新的 4 步结构

每一关只做 4 件事：

**第 1 步：目标卡**

告诉用户这一关学什么，完成标准是什么。

```
┌─────────────────────────────┐
│  第 3 关：文件导航          │
│                             │
│  🎯 你要学会：进入文件夹   │
│  📋 任务：进入 documents   │
│  ✅ 完成：终端显示 documents│
│                             │
│  💡 为什么要学这个？        │
│  终端能力 = Agent 操作文件   │
│  的"手"。学会这个，你就    │
│  能理解 Agent 是怎么"动手"  │
│  操作文件的。               │
│                             │
│  [开始]                   │
└─────────────────────────────┘
```

**第 2 步：动手任务**

用户必须操作，不能只看解释。

- 前期：选词拼装
- 后期：自由编写
- 每关必须有"用户动手"的环节，不能纯看

**第 3 步：错误提示**

用户出错时，系统给出渐进式提示，而不是直接给答案。

```
用户第一次错：暗示（"你确定这个命令能'去'到那个地方吗？"）
用户第二次错：明示方向（"你想'去'某个地方，应该用 Set-Location"）
用户第三次错：给答案（直接显示正确命令）
```

**第 4 步：AI 视角啊哈时刻**

每关结束必须告诉用户：这个能力将来在 AI / Agent 中怎么用。

每关最后必须出现固定模块：

```
┌─────────────────────────────┐
│  🤖 AI 视角解释            │
│                             │
│  你刚刚学会了 Get-ChildItem │
│  （列出当前目录的文件）。   │
│                             │
│  在真实 Agent 中，这类能力  │
│  可以帮助 Agent 查看文件夹  │
│  里有哪些文件。             │
│                             │
│  以后当 Agent 要整理资料、  │
│  查找文件、读取项目结构时，  │
│  就会用到类似能力。         │
│                             │
│  [下一关 →]                │
└─────────────────────────────┘
```

### 10.3 每关的"AI 视角解释"必须具体化

不能只说"这个能力对 Agent 很有用"，而要具体说明：

- 这个能力在 Agent 的哪个环节被用到
- 用户以后在实际操作中会怎么用
- 如果不会这个能力，指挥 Agent 时会遇到什么问题

## 十一、NPC 小黑的重新定位

### 11.1 小黑不是普通教程助手

小黑是整个产品的情感线和认知闭环。

### 11.2 小黑的身份

- **一开始：** 看起来是普通 NPC 助手
- **W6 第 5 关：** 揭示小黑本身就是一个初级 Agent
- **全程：** 小黑也在"成长"——从新手向导变成技术搭档

### 11.3 认知闭环

```
用户先使用小黑（W1-W5）
    ↓
习惯 AI 辅助学习
    ↓
学习 Agent 原理（W6）
    ↓
发现小黑就是 Agent（W6-5，认知闭环）
    ↓
最后自己搭建类似小黑的 Agent（W7）
```

### 11.4 小黑必须承担的功能

| 功能 | 说明 |
|------|------|
| 降低小白恐惧 | 用大白话解释技术概念，不吓人 |
| 解释技术概念 | 每个新概念出现时，用小黑的话解释 |
| 提供错误提示 | 用户卡住时渐进式提示 |
| 连接当前知识与 Agent 应用 | 在"AI 视角解释"环节说话 |
| 推动剧情和成就感 | 用户做对时的鼓励，通关时的庆祝 |

### 11.5 小黑的提示风格

- **不要太学术**——不用术语，用大白话
- **不要太长**——每次说话控制在 2-3 句话
- **要像队友**——不是"老师对学生"，而是"老手带新手"
- **可以幽默**——偶尔吐槽、开玩笑，增加人格感
- **但不能废话太多**——有信息量，不纯凑数

### 11.6 小黑的成长线

| 阶段 | 小黑的状态 | 对话风格 |
|------|------------|----------|
| W1-W2 | 新手向导，自己也还在学 | 热情但偶尔说错话，会承认"这个我之前也搞混过" |
| W3-W5 | 技术搭档，能力增长了 | 更自信，能解释更深入的概念 |
| W6 | 揭示身份：小黑就是 Agent | 情感高潮，小黑"坦白" |
| W7 | 战友，陪用户搭建自己的 Agent | "你现在能搭出像我这样的 Agent 了" |

## 十二、游戏化设计原则

### 12.1 核心原则

游戏化的目的不是"加积分系统就完事"，而是**针对小白的心理反应逐一破解**。

### 12.2 针对"看不懂英文"的设计

- 命令单词级拆解（Get=获取，Content=内容）
- 中文别名（输入"看看"也能执行）
- 真实命令对照（告诉用户真实世界里怎么打）

### 12.3 针对"会偷懒"的设计

- 删掉"帮我填入"按钮
- 改为选词拼装（必须理解才能选对）
- 保留"提示"按钮（渐进式，3 次后才给答案）

### 12.4 针对"不知道要干嘛"的设计

- 每关开头有目标卡
- 每关结尾有完成标准
- 有全局进度地图

### 12.5 针对"学完没感觉"的设计

- 每关有"啊哈时刻"（之前做不到但现在能做到的事）
- 每关有"AI 视角解释"（告诉用户学的东西以后怎么用）

### 12.6 针对"认知压力累积"的设计

- 每隔 3-4 关插一个"自由探索关"或"彩蛋关"
- 降低认知压力，让用户"喘口气"

## 十七、当前不做什么（避免的问题）

1. **不要继续无边界加关卡**——总关数控制在 50 关以内，追求质量不是数量
2. **不要把产品写成普通编程课**——编程是手段，Agent 操作员是目标
3. **不要把 C 语言做得太深**——能看懂、能改就够了，不要求从零写
4. **不要把 AI 启蒙做成理论课**——建立认知，不教数学和算法
5. **不要一开始就工程化重构**——v1.x 继续单文件，v2/v3 再拆分
6. **不要加社区、排行榜、账号系统这些非核心功能**——先把核心体验做好
7. **不要让每关解释太长**——用"AI 视角解释"模块，不在正文中写长文
8. **不要让用户不知道为什么要学当前内容**——每关目标卡必须回答"为什么"
9. **不要只教技术，不解释它和 Agent 的关系**——AI 认知层必须贯穿全程
10. **不要让小白觉得自己在学一堆没关系的知识**——学习路径必须有清晰的逻辑链

## 十八、最终方向总结

《Agent新手村》是一款面向零基础小白的 AI Agent 操作员闯关训练系统。

它不是单纯教编程，也不是单纯讲 AI，而是通过游戏化方式，把 AI 认知、终端、编程逻辑、Python、环境配置、C 语言底层理解、Agent 原理和工作流实战串成一条完整成长路径。

**核心不是让用户死记知识，而是让用户建立一个认知模型：**

```
AI 如何理解任务
Agent 如何使用工具
程序如何运行
环境如何支撑 Agent
人如何指挥 AI 完成工作
```

**所有内容都必须服务于最终目标：**

**让小白从"不会用 AI"，成长为"能和 AI 协作、能操作 Agent、能搭建简单工作流"的 AI Agent 操作员。**
